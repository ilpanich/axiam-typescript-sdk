    Function ssfStreamInputFrom

    • ssfStreamInputFrom(stream: SsfStream): SsfStreamInput

      Read-modify-write for ssf.updateStream (§32.2): the plain converter. authorization_header is left absent — absent keeps the stored header (unless the update moves endpoint_url to another origin, §32.3 rule 5) — and so is clear_authorization_header.

      events_requested is always sent, as read — [] stays [], because omitting it would reset a receiver's narrowing to every allowed event — and expected_updated_at is the updated_at of the read, the server's own string (contract 1.61, 1.62, §32.2): the replacement lands only if nobody wrote the stream since, else 409 — reload, then retry. Delete it from the body to fall back to the server's version-at-request.

      The caller's duty (contract 1.62, §32.2). This function cannot know that you are about to lower events_allowed, so it does not cut events_requested: if you lower the ceiling on the result you MUST cut events_requested to the new events_allowed yourself, or the server answers 400 for a request outside the ceiling. Remember the three meanings of events_requested on an update — absent resets the stream to every event of events_allowed (widening what the receiver narrowed), [] is stored as the receiver's "none", a list is stored as given and refused (400) outside events_allowed — and that a stream written since you read it (the receiver included) is 409. ssfStreamInputWith is the form that takes the changes and does the cut for you.
